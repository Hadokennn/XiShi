## 概念巩固

### 一、async / asyncio

#### 核心定义

- **coroutine（协程）**：可以"中途暂停 + 之后恢复"的函数。`async def` 定义。本质是带状态的对象，**不是线程**。
- **event loop（事件循环）**：单线程调度器。从就绪队列拿 coroutine 跑，遇到 `await` 挂起去跑别的，IO 回来再恢复。
- **await**：让出控制权 + 标记恢复点。**不是"等待"**，是"我要 IO 了，loop 你去忙别的"。

#### 为什么 LLM 项目几乎必须 async

LLM 调用一次 1-30 秒全是网络 IO 等待。同步阻塞 = 一个请求卡 5 秒 = 后续请求堆积；异步 = 单进程扛几百个并发 LLM 等待。

#### 三大陷阱

1. **忘了 await**：`fetch()` 只生成 coroutine 对象不执行，Python 只 warning 不报错
2. **同步调用混进 async**：`time.sleep()` / `requests.get()` / 同步 DB driver 任何一个都卡死整个 loop。所以选 `asyncpg` 不选 `psycopg2`
3. **以为 async = 多线程**：asyncio 整个就一个线程，CPU 密集任务用 async 完全没用

#### 关键 API

| API | 用途 | JS 类比 |
|---|---|---|
| `await coro` | 等单个 coroutine | `await promise` |
| `asyncio.gather(a, b, c)` | **并发**等多个 | `Promise.all([...])` |
| `asyncio.create_task(coro)` | fire-and-track | JS 调用 async 函数即开始 |
| `asyncio.run(main())` | 入口启动 loop | Node 顶层 await |

#### 与 JS 的关键差异

JS：`fetch()` 立刻推进 microtask queue，**调用即开始**。
Python：`async def` 调用**只生成对象不执行**，必须显式 await 或交给 loop。

#### 面试拷问准备

- **GIL 存在情况下 asyncio 有意义吗？** → 解决 IO 并发，不是 CPU 并发
- **async vs threading？** → 协作式 vs 抢占式，单线程无锁 vs 多线程要锁
- **怎么在 async 里调同步库？** → `loop.run_in_executor()` 扔到线程池

### 二、uv

#### 一句话

**`uv` ≈ Python 世界的 `pnpm`**。Rust 写的、Astral 团队 2024 发布、一站式 Python 工具链。

#### 取代了哪些工具

| 过去 | uv |
|---|---|
| `pyenv`（管 Python 版本） | `uv python install 3.13` |
| `python -m venv`（建虚拟环境） | `uv venv` |
| `pip install`（装包） | `uv add` |
| `pip-tools` / `poetry`（锁依赖） | `uv lock` / `uv sync` |
| `pipx`（装 CLI 工具） | `uv tool install` |

#### 三个关键文件

```
pyproject.toml    声明要什么（≈ package.json）
uv.lock           锁定精确版本（≈ pnpm-lock.yaml）
.venv/            自动创建的虚拟环境（≈ node_modules）
```

`.venv/` **必须 gitignore**；`uv.lock` **必须 commit**（保证团队/CI 装出一样的环境）。

#### 为什么选 uv

- **速度**：装一个项目快 10-100 倍（Rust + 全局缓存 + 并行下载）
- **统一**：一个二进制取代 pyenv + pip + venv + pip-tools 四件套
- **lockfile 真的能锁**：抄了 pnpm 设计，确定性强
- **不需要 Python 引导自身**：单二进制 brew 装一次就行

#### 关键陷阱

- 别在 uv 项目里直接 `pip install`——绕过 `pyproject.toml` 破坏锁定。永远 `uv add <pkg>`
- 跑命令用 `uv run python xxx.py`，不要 `python xxx.py`（后者用系统 Python）

### 三、Postgres + pgvector

#### Postgres ≈ 后端世界的 React

不是"哪个最新"，是"行业默认"。开源、稳定 30 年、功能最全的关系型数据库。

#### 关系型数据库核心

```sql
CREATE TABLE atoms (
  id UUID PRIMARY KEY,
  content TEXT NOT NULL,
  zone_ids TEXT[],          -- Postgres 支持数组（多数 DB 不支持）
  metadata JSONB,           -- Postgres 支持 JSON 当列存
  event_time TIMESTAMPTZ,   -- 带时区时间
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

#### 为什么不用 MongoDB / SQLite / MySQL

- **MongoDB**：JSON-first，但夕拾数据有强结构（7 实体 + 外键），关系型更合适
- **SQLite**：开发期能用，但 pgvector 没 SQLite 版本，多用户/并发也不行
- **MySQL**：JSONB / 数组 / 全文检索 / pgvector 全比 Postgres 弱

#### pgvector 是什么

Postgres 有个机制叫 **extension（扩展）**——第三方写 C 代码扩展 Postgres，注册新的数据类型/索引/函数。pgvector 给 Postgres 加了：

- 新数据类型 `vector(N)`（N 维浮点数组）
- 三种距离运算符：`<->`（L2）、`<=>`（cosine）、`<#>`（内积）
- 两种向量索引：**HNSW** 和 **IVFFlat**

```sql
CREATE EXTENSION vector;            -- 启用扩展

CREATE TABLE atoms (
  id UUID PRIMARY KEY,
  content TEXT,
  embedding vector(1536)            -- 存 embedding
);

-- 查询：找和某个向量最相似的 10 条
SELECT id, content
FROM atoms
ORDER BY embedding <=> '[0.1, 0.2, ...]'::vector
LIMIT 10;
```

#### 为什么 pgvector 而不是 Pinecone / Chroma / Qdrant

- **一份 DB 管两种数据**：Atom 元数据和 embedding 在**同一行**，可以一条 SQL 同时过滤"亲子区 + 最近 30 天 + 向量最相似"——专用向量库做不到这种 hybrid query
- **事务保证**：写入 atom 和 embedding 在一个事务里，要么都成要么都失败
- **运维成本**：少一个服务要维护
- **代价**：百万级以上数据量时性能不如专用向量库，但夕拾几年到不了那量级

#### HNSW 索引（W5 才用，先建立直觉）

向量检索核心问题：100 万个 1536 维向量找最相似的 10 个，暴力 cosine 太慢。HNSW（Hierarchical Navigable Small World）= 多层图结构，上层稀疏跳跃，下层密集精搜。召回率 95%+，速度快几个数量级。
